## Directory Purposes

**`src/`:**
- Purpose: All application source code
- Contains: Components, hooks, styles, assets
- Key files: `main.jsx`, `App.jsx`, `DervishiGroup.jsx`, `admin/Admin.jsx`

**`src/lib/`:**
- Purpose: Shared utilities and state management
- Contains: Custom React hooks (useLocalStorage, useAuth, useTheme, useHashRoute, useI18n)
- Key files: `store.js` (state hooks), `i18n.js` (translation system)

**`src/admin/`:**
- Purpose: Admin dashboard application
- Contains: Admin layout, authentication, CRUD forms, data management
- Key files: `Admin.jsx` (entire admin interface)

**`src/assets/`:**
- Purpose: Static images
- Contains: SVG and PNG files
- Key files: `hero.png` (likely large hero image for showroom section)

**`public/`:**
- Purpose: Static web assets served as-is
- Contains: favicon.svg
- Committed: Yes
- Generated: No

## Naming Conventions

**Files:**

- PascalCase for React components: `App.jsx`, `DervishiGroup.jsx`, `Admin.jsx`
- lowercase for utility modules: `store.js`, `i18n.js`
- CSS alongside components: `App.css`, `index.css` (global)
- Assets in `assets/` directory with descriptive names: `hero.png`, `react.svg`

**Directories:**

- lowercase with dashes (package.json convention): `node_modules/`, `public/`, `src/`
- lowercase for subdirectories: `lib/`, `admin/`, `assets/`
- No nested component directories (flat structure)

**Functions (in hooks/utils):**

- camelCase for hook names: `useLocalStorage`, `useAuth`, `useTheme`, `useHashRoute`, `useI18n`, `useConfirm`
- camelCase for utility functions: `fileToBase64`, `downloadCSV`, `toast`
- Constants in SCREAMING_SNAKE_CASE: `ADMIN_CREDENTIALS`, `DEFAULT_SOLAR`, `DEFAULT_SETTINGS`, `LANGUAGES`, `TRANSLATIONS`

**Variables:**

- camelCase for component state: `items`, `setItems`, `isAdmin`, `tab`, `setTab`
- Single-letter state vars in loops: `k`, `f`, `c`, `i`, `x`, `p`, `h`, `o`
- Prefixes for state management: `dg_` for localStorage keys (Dervishi Group prefix)

**Types/Objects:**

- Inline object types in prop validation
- Field definitions follow structure: `{ k: keyName, label: "Display", type: "text", required: true }`
- Translation objects organized by feature: `sq.nav`, `sq.hero`, `sq.services`, `sq.admin`, etc.

## Where to Add New Code

**New Feature:**

- **Public site section:** Add new section component in `src/DervishiGroup.jsx`
  - Example pattern: Hero, Services, Products, etc. are all inline functions
  - Add state with `useLocalStorage` if data persistence needed
  - Add translations in `src/lib/i18n.js` under corresponding language keys
  - Add route handler in `useHashRoute` if needs dedicated page

- **Admin feature:** Add new tab component in `src/admin/Admin.jsx`
  - Follow pattern: Define fields array, use `useLocalStorage`, handle CRUD
  - Add to `tabs` array (line 20-31) for navigation
  - Create tab render condition (line 73-82 for tab === "newTab")
  - Add icon to `ICONS` object (line 9)
  - Add translations to `t.admin` in `src/lib/i18n.js`

**New Component/Module:**

- **Reusable component:** If used in multiple places, extract to separate file
  - Location: `src/` root or `src/components/` (not currently used)
  - Import in `App.jsx` or relevant feature file
  - **Current practice:** Inline components within feature files for simplicity

- **Utility hook:** Add to `src/lib/store.js`
  - Follow pattern of existing hooks (useState init function, useEffect setup)
  - Export hook from store.js
  - Import with destructuring in component

- **Translation strings:** Add to corresponding language in `src/lib/i18n.js`
  - Add key under feature section (e.g., `admin.newFeature: "Label"`)
  - Access via `t.admin.newFeature` after `const { t } = useI18n()`

**Utilities:**

- **Shared helpers:** Add to `src/lib/store.js` (existing pattern: `fileToBase64`, `downloadCSV`, `toast`)
  - Pure functions or custom hooks
  - Export from store.js for use in components

- **Global state:** Use `useLocalStorage` hook for persistent state
  - Or implement similar pattern for non-persistent global state
  - Avoid creating new state management library (keep monolithic)

**Styling:**

- Global styles: `src/index.css`
- Component styles: `src/App.css` (mixed with old template code)
- CSS variables defined in `:root` for theming (--text, --bg, --accent, etc.)
- Dark mode: Media query at line 33 in `index.css` with `@media (prefers-color-scheme: dark)`
- Theme toggle updates `document.documentElement.setAttribute("data-theme", ...)` in `useTheme` hook
